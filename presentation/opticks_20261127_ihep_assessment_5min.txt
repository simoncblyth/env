.. s5_talk:: 

   Opticks applies GPU ray tracing to optical photon simulation.


.. comment

   Opticks is an open source package that applies GPU ray tracing to optical photon simulation.

   
.. comment

   This render illustrates the many millions of photons resulting from a 200GeV muon crossing the JUNO scintillator.
   Finding intersects between rays representing the photons and the detector geometry is the bottleneck for simulation. 
   Offloading the optical simulation to the GPU can eliminate this bottleneck.   
   I developed the Opticks package to do exactly that.

3. Scaling Opticks with Server/Client Architecture
--------------------------------------------------


.. raw:: html

     <p style="margin-bottom:52mm;" />

.. class:: huge

    Geant4 + Opticks + NVIDIA OptiX : Production Scaling ?


.. class:: normal

   * hard to make good use of GPU resources, gets harder with each generation

     * :r:`under-utilized GPUs`

   * monolithic scaling Opticks ?

     * GPU idle while : Geant4 init + non-optical simulation : :r:`wasteful of GPU resources`

   :b:`=> Client-Server architecture`

   * separate GPU optical simulation into OpticksServer
   * share server between CPU nodes



.. s5_talk::

   How to scale Opticks is an open question

   Scaling monolithically means that GPUs sit idle while Geant4 is initialized and
   the non-optical simulation is done.

   Can server-client fix : lack of GPU resources + underutilized GPUs

:small:`Shader Execution Reordering (SER) - re-grouping to reduce divergence`
----------------------------------------------------------------------------------------------


.. class:: small

    SER : GPU ray-tracing optimization - dynamically groups threads : reduces execution + memory divergence

.. class:: small

    +----------------------------------------------------------+---------+-----------+---------------+
    | 100M optical photons from JUNO CD center - kernel time   |  no SER |  with SER |               |
    |                                                          +---------+-----------+---------------+
    |                                                          | 21 s    |  12 s     | 1.75x speedup |
    +----------------------------------------------------------+---------+-----------+---------------+
    



    * BNL (DUNE) Opticks-fork user (Simphony) users report[1] 16x speedup from SER

    Opticks simulation time very sensitive to geometry + geometry modelling

    * BUT: large difference in SER benefit warrants investigation + optimization


.. class:: small

    [1] https://arxiv.org/abs/2608.21396 


.. comment

:tiny:`Mitigating warp divergence in GPU optical photon Monte Carlo: an order of magnitude speedup with Shader Execution Reordering`
 


:small:`GPU Architecture : Memory Tiers (Clock Frequency ~2.5 GHz)` 
-------------------------------------------------------------------------

.. class:: small

    +------------------------+------------------------+---------------------+-----------------------+
    | Memory Tier            | Latency (Clock Cycles) | Aggregate Bandwidth | Typical Capacity      |
    +========================+========================+=====================+=======================+
    | Registers              | ~1 cycle               | ~70–80+ TB/s        | 256 KB per SM         |
    +------------------------+------------------------+---------------------+-----------------------+
    | L1 Cache / Shared Mem  | ~20–30 cycles          | ~15–20 TB/s         | 128–256 KB per SM     |
    +------------------------+------------------------+---------------------+-----------------------+
    | L2 Cache               | ~150–250 cycles        | ~3–12 TB/s          | 6–96 MB (GPU-wide)    |
    +------------------------+------------------------+---------------------+-----------------------+
    | VRAM (HBM / GDDR)      | ~300–600+ cycles       | ~1–4.8 TB/s         | 8–192 GB (Off-chip)   |
    +------------------------+------------------------+---------------------+-----------------------+



.. raw:: html

     <p style="margin-bottom:165mm;" />

:small:`Opticks CSG Impl guided by Kernel Profiling (NVIDIA Nsight Compute)`
------------------------------------------------------------------------------

.. sidebar:: :small:`CSG Optimization`

    .. class:: small

        Complete Binary Tree (CBT) [:b:`current approach`]
           navigate by bit twiddling level order index,
           BUT sparse for deep trees (complex shapes)

        Reverse Polish Notation (RPN) [:r:`in development`]
           inherent postorder, navigate by spans, :strike:`padding` 
       

        1. CBT => RPN (halves JUNO CSG nodes)
        2. shrink node, 64 => 4 byte

        Aims:

        * every JUNO solid in L2 cache line (128 bytes)
        * maximize L2 cache-line prefetching   
        * avoid "thrashing the cache"
     




.. class:: normal

    JUNO+Opticks simulation kernel profile insights:

    1. trace > 100x propagation => :r:`intersect limited`  
    2. entire JUNO CSG fits inside L2 cache (64MB) 
    3. ~12% L2 cache stalls from CSG node navigation

:small:`GPU Hit Merging : High Level Parallelization with CUDA Thrust`
----------------------------------------------------------------------------


.. raw:: html

    <pre style="mypretiny">
    struct key_functor {   //  <span class="r">Bitwise-OR (pmtid,timebucket) </span>
      float    timewindow;
      uint64_t operator()(const sphotonlite& p) const // 16+48 = 64
      {
         return (uint64_t(p.identity()) << 48) | uint64_t(p.time/timewindow);
      }  
    };
    </pre>


.. class:: small

  Opticks/sysrap ``SPM::merge_partial_select`` using CUDA Thrust (higher level C++ way to use CUDA) 

  +--------------------+-------------------------+-----------------------------------------------------+
  |  Thrust method     |  Action                 |  Note                                               |
  +====================+=========================+=====================================================+
  | ``copy_if``        |  photon -> hit          | using flagmask                                      |
  +--------------------+-------------------------+-----------------------------------------------------+
  | ``transform``      |  hit -> key             | bitwise-OR (pmtid, timebucket)                      |
  +--------------------+-------------------------+-----------------------------------------------------+
  | ``sort_by_key``    | hit, key -> hit         | hit ordered with same (pmtid,timebucket) contiguous |
  +--------------------+-------------------------+-----------------------------------------------------+
  | ``reduce_by_key``  | hit, key -> hitmerged   | merge two hit : earlier time, sum hitcount          |
  +--------------------+-------------------------+-----------------------------------------------------+
  

  ``https://github.com/simoncblyth/opticks/blob/master/sysrap/SPM.cu``

  ``https://github.com/simoncblyth/opticks/blob/master/sysrap/sphotonlite.h``


.. s5_talk::

   The key to GPU hit merging is this bitwise OR of pmtid and timebucket.
