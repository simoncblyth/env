.. s5_talk:: 

   Opticks applies GPU ray tracing to optical photon simulation.


.. comment

   Opticks is an open source package that applies GPU ray tracing to optical photon simulation.

   
.. comment

   This render illustrates the many millions of photons resulting from a 200GeV muon crossing the JUNO scintillator.
   Finding intersects between rays representing the photons and the detector geometry is the bottleneck for simulation. 
   Offloading the optical simulation to the GPU can eliminate this bottleneck.   
   I developed the Opticks package to do exactly that.

3. Scaling Opticks with Server-Client Architecture ?
-----------------------------------------------------


.. sidebar:: :small:`Problems with GPUs`

   .. class:: small

       1. Not enough of them

       2. Difficult to keep them busy

          * GPU idle while : G4 init + non-optical sim.


       **Client/Server architecture:**

       * GPU optical simulation by server
       * share server between CPU nodes
       * adjustable client:server ratio in MC production

         * => :b:`makes GPU utilization tunable`


       :r:`Strong potential - but pushing the envelope`



.. class:: normal


   This year:

   * :b:`prototype server-client proved the idea`
   * succeeded in small scale tests

   BUT, Hand-crafted server problematic:

   * robustness for large scale MC production ?
   * practicality for system + network admin ?

.. raw:: html

   <p style="margin-bottom:30mm;" />

.. class:: normal


   Aim to make a viable solution for MC production:

   * adapt Opticks to an industry standard server **NVIDIA Triton Inference Server**

     * :b:`NVIDIA maintained open source server software`
   






.. s5_talk::

   Client-Server architecture is an obvious way
   to solve the lack of GPU resources and underutilized GPUs -
   but it is very much pushing the envelope.

   This year have proved that it can be done.

   Proving that it can be a practical solution for
   large scale MC production requires more work.

:small:`Shader Execution Reordering (SER) - re-grouping to reduce divergence`
----------------------------------------------------------------------------------------------


.. class:: small

    SER : GPU ray-tracing optimization - dynamic thread re-grouping (Ada + Blackwell) : reduces execution + memory divergence

.. class:: small

    +----------------------------------------------------------+---------+-----------+---------------+

:small:`Opticks CSG Impl guided by Kernel Profiling (NVIDIA Nsight Compute)`
------------------------------------------------------------------------------

.. sidebar:: :small:`CSG Optimization`

    .. class:: small

        Complete Binary Tree (CBT) [:b:`current approach`]
           navigate by bit twiddling level order index,
           BUT sparse for deep trees (complex shapes)

        Reverse Polish Notation (RPN) [:r:`in development`]
           inherent postorder, navigate by spans, :strike:`padding` 
       

        1. CBT => RPN (halves JUNO CSG nodes)
        2. shrink node, 64 => 4 byte

        Aims:

        * every JUNO solid in L2 cache line (128 bytes)
        * maximize L2 cache-line prefetching   
        * :b:`avoid "thrashing the cache"`
     


.. class:: normal

    JUNO+Opticks simulation kernel profile insights:

    1. trace > 100x propagation => :r:`intersect limited`  
    2. entire JUNO CSG fits inside L2 cache (64MB) 
    3. ~12% L2 cache stalls from CSG node navigation
